# ElevenLabs 语音演绎

## 行为

- `eleven_v3` 默认启用音频标签。其他模型不通过版本号推测能力；在语音 API 设置中确认支持后，勾选「此模型支持语音演绎标签」。切换模型会重置这一覆盖值。
- 私聊及群聊的语音条生成协议不再依赖 TTS 绑定或模型能力开关。每条新语音条的原文必须至少包含一个标签，按角色、上下文和语义转折生成；口音按角色或剧情要求使用。普通文字消息不添加标签。缺标签时补提可能增加聊天 LLM 用量和等待时间。
- 语音条协议支持嵌套一层方括号，例如 `[语音条:[curious]你怎么来了？]`。验收阶段 `label` 和 `speechPerformanceText` 均保留带标签原文；角色语音气泡下直接展示原文，旧消息缺标签时明确显示不符合规则。合成时另行提取纯台词和演绎，双语消息只合成原文。
- 新回复在聊天引擎交付前检查语音条：遗漏标签时调用绑定的聊天 LLM 补齐，带标签的结果同时用于消息解析和「编辑回复」原文。普通文字及已有有效标签不额外请求。旧消息仍在合成前按需补标签；私聊编辑器会带回已保存且正文匹配的演绎。LLM 只返回插入位置和标签，程序保留台词，最多尝试两次。失败后报错，不交付无标签的新语音回复；流式预览仍可能暂时显示未补齐内容。
- 新消息自带有效标签时不额外调用补标签 LLM。补标签有内存缓存及并发去重，成功合成后演绎文本随音频保存。重复播放复用音频，正文或已保存演绎变化时缓存失效。升级本身不主动重新合成已有音频。
- 其他语音模型合成前移除本功能识别的音频标签，保留 `[姓名]` 等普通方括号内容。

## 当前边界

标签集合是本项目的候选集合，不是官方固定枚举；接受标签不代表模型一定执行。口音、平静语气及中文音色表现需要实际试听。未知未来模型不会自动启用。本轮重点覆盖聊天语音条，其他入口通过统一 TTS 服务获得补标签能力，但未提供角色或上下文的入口仅根据台词判断，并使用默认 API 绑定。

## 验证

离线检查（需先安装项目依赖）：

```sh
node scripts/check-elevenlabs-audio-tags.mjs
npx tsc --noEmit
npm run build
```

回归脚本执行真实的标签工具、标签插入和富消息解析函数；解析器外围的动作清理、工具协议、自定义 APP 指令依赖被桩替换，因此不代表完整集成测试。覆盖：模型能力判断、口音标签、保留普通方括号、Unicode 台词不变、非法位置/视觉动作拒绝、语音标签嵌套、语音内空行、旧语音格式。

本次编辑环境仅提供仓库读写，以上命令尚未运行，未调用收费的 LLM/TTS，也未试听。部署前需运行检查，并实测中文音色、双语消息、群聊独立绑定、失败重试、重复播放不计费以及修改演绎后重生成。
